Summary: Path /{lang} cannot DNS-map to R2; implement via Worker Cache→R2 or separate R2 host.

[question]
https://onlinefreetools.org/{lang} 能否配置指向R2，如果可以改R2，怎么实现

[try to solve]
结论：不能把 apex 上仅路径 `/{lang}` 用 DNS/R2 自定义域「配置指向」R2——自定义域是整主机名级，且 `onlinefreetools.org` 已是 Pages，不能再挂同一主机的 R2 自定义域做路径分流。可行实现只有 Worker 读 R2。

方案 A（推荐若坚持首页只走 R2，改动小）：`serveHomeHtml` 跳过 Assets，只走 Cache→R2 `_pages/{lang}/index.html.gz`→gunzip（与工具页相同）；upload:r2 已含首页备份；可不再依赖 git 里的 `public/{lang}/index.html` 热更新（仍可保留作兜底）。代价：冷路径接近工具页 miss ~300ms。

方案 B（改 R2 布局）：上传明文 key 对齐公开路径如 `zh/index.html`（非 `.gz`），Worker 映射 `/{lang}/`→该 key；仍须 Worker，不能 DNS 直挂。公开桶/自定义域只适合独立子域（如 `pages-cdn…`），无法单独接管 apex 的 `/{lang}`。

方案 C：R2 自定义域挂子域——解决不了 `onlinefreetools.org/{lang}`。

不建议为首页单独改 R2 公开布局；现状 Assets 优先更优。若做方案 A，改 `r2Pages.serveHomeHtml` + 文档/ops，不必改桶绑定。
