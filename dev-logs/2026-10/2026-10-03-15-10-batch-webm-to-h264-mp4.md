## Eighth locally completed item

`/tools/batch-convert-webm-files-to-mp4-files` accepts up to 20 local WebM videos and processes them one at a time. Each row inspects the real WebM tracks, requires an H.264 encoder for the source dimensions, encodes AVC video and AAC when the source has audio, and reopens the output to verify MP4/H.264/AAC and plausible duration. The row reports source/output codecs, dimensions, duration, size before/after and a specific failure; successful rows remain available when another fails or the user stops. Duplicate source names receive distinct MP4 download names. Adding a file preserves completed outputs; removing a row releases its result. A slow automatic sample cannot overwrite a user-selected file.

The page downloads each MP4 separately instead of assembling a large in-memory ZIP. With OPFS, even smaller batch outputs remain in origin storage until Clear or row removal; the vendor module's default small-output Blob copy remains unchanged for single-file tools. Without OPFS, the code caps each source at 80 MiB and all retained results together at 128 MiB, with an actionable row error if the budget is full. With OPFS, the source code cap is 500 MiB. These are code limits, not validated maxima. The largest WebM input tested here was 108 MiB / 90 seconds; its resulting MP4 was about 11 MiB, so a >80 MiB batch output remains unverified.
