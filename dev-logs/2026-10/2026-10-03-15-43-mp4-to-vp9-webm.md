## Tenth locally completed item

`/tools/convert-an-mp4-file-to-a-webm-file` accepts one local MP4, reads real video/audio tracks, checks source decoders and VP9/Opus target encoders, then uses Mediabunny `WebMOutputFormat` for genuine WebM output. It reopens the output to require VP9 video, Opus if the source had sound and a plausible duration. A silent MP4 remains video-only; undecodable HEVC and unavailable VP9/Opus encoders produce clear errors without audio-only false success. The page shows input/output codecs, dimensions, duration and byte sizes, plus a preview and download. It says clearly that VP9 may be larger than the original MP4.

The existing shared loader gained an explicit `convertMp4ToWebm` entry and a WebM target extension while its MP4 default remains the same. OPFS retains outputs until Clear; the source input code cap is 500 MiB with OPFS and 80 MiB without, not a universal tested maximum. A real >80 MiB, 90-second MP4 yielded a downloaded 406,254,226-byte VP9 WebM in the latest local Chrome test, demonstrating why size reduction cannot be promised. For explicit OPFS jobs larger than 80 MiB, a failed OPFS output-open now returns a storage error instead of falling back to an unbounded in-memory result; a fault-injection browser test passed.
