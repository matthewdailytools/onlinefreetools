## Context

The site lost nearly all Search impressions on 2026-10-06, which lines up with the September 2026 spam update (see `docs/seo/reviews/2026-10-13/01-analysis-review.md`). The request had two parts:

1. Stop dev logs from being crawled and indexed: add a robots.txt block and page-level noindex.
2. Review every tool page against competitors and add information gain, without doing anything that looks like scaled content abuse.

`git pull` reported "Already up to date".

## Process

**Devlogs.** `public/robots.txt` is a static file. Dev log HTML is generated by `buildDevLogs()` in `scripts/build-site.mjs`. Before this change, only `Visibility: project` posts got `noindex, nofollow`. People posts and the index pages were indexable and listed in the sitemap through `collectDevlogSitemapEntries()`. Worker Assets serve the pages directly (`html_handling: none`). Only `/devlogs/` goes through the Worker route.

**Robots vs. noindex conflict.** Google's documentation says noindex only works if the crawler can fetch the page. If robots.txt blocks a URL, Googlebot never sees the noindex, and already-indexed URLs can stay in the index as "Indexed, though blocked by robots.txt". Doing both at once would undo the noindex. The user picked a two-phase rollout:

- Phase 1 (this change): noindex every devlogs page, remove all devlogs URLs from the sitemap, and leave robots.txt open.
- Phase 2 (later): once Search Console confirms the URLs are excluded by noindex, add `Disallow: /devlogs/`.

**Tool review scope.** There are 317 tools in 10 locales. Rewriting all of them in one pass is the pattern the spam policies describe, and the repo rules require research-driven rewrites with at least three review rounds per locale. So the user chose a full read-only audit first, with page edits to follow in small batches.

## Root cause / analysis

The audit (`scripts/qa/audit-tool-info-gain.mjs`) reads the merged catalog, the 10-locale i18n shards, and the Page sources. It checks:

- Visible info-gain copy only: description, How it works and its steps, Why choose, Formula/Rules, Example, Use cases, FAQ, Disclaimer, and References.
- References hard-coded in `renderToolReferencesSection({ links })` inside `*Page.ts`. The first run missed these and wrongly reported 228 tools without references.
- Template reuse across tools: 5-word shingle overlap, plus each tool's most similar neighbour by Jaccard similarity.
- Locale parity: keys missing in a locale, or values left identical to the English text.
- Search Console data from before the drop: page impressions from the 2026-09-10 export, and "Crawled, currently not indexed" URLs from the 2026-08-12 and 2026-09-07 exports.
- Launch date. 102 tools launched after 2026-09-10, so zero impressions means "no data" for them, not "no demand".

Key findings:

- **how-to-calculate family (60 tools):** the text is not templated (nearest-neighbour similarity at most 0.08). It is extremely thin. Many pages have under 200 words, Use cases like "Physics homework.", and FAQ answers like "Rejected.". Several non-English locales still contain English sentences. That is a scale-plus-thinness signal, not a duplicate-text one.
- **prompt family (10 tools):** the strongest template reuse on the site. Average shared-skeleton share is 0.63 and nearest-neighbour similarity is 0.52.
- **Missing sections site-wide:** 222 tools lack a Why choose section and 95 have fewer than three How steps. Backfilling these on all pages at once would itself be a scaled-content risk.

## Solution

Devlogs:

- `scripts/site/devlogs.mjs`: new `DEVLOGS_ROBOTS_CONTENT = 'noindex, nofollow'`. `collectDevlogSitemapEntries()` returns `[]` while devlogs are noindex.
- `scripts/build-site.mjs`: every post and every index page gets `robotsContent: DEVLOGS_ROBOTS_CONTENT`, regardless of Visibility.
- `public/_headers`: sends `X-Robots-Tag: noindex, nofollow` for `/devlogs/*`.
- `src/index.ts`: the `/devlogs/` Worker route sets the same header.
- `public/robots.txt` is unchanged on purpose.
- Rules updated to match: `dev-logs.mdc`, `seo-html-defaults.mdc`, `project-core.mdc`, and `.github/copilot-instructions.md`.

Audit:

- `npm run audit:ig -- --out-dir=docs/seo/reviews/2026-10-13` writes `04-tool-ig-audit.md` and `.csv`.
- Buckets:
  - A, consolidate-review (71): the how-to-calculate and prompt families. Decide whether to merge into hubs, redirect with 301, or noindex before adding any copy.
  - B, enrich-first (55): tools that had impressions before the drop and have clear gaps. The report lists a top-10 first batch.
  - C, enrich-later (11).
  - D, low-priority (180).
- `03-todo.md` now includes the deploy step, the phase-2 robots step, and the bucket follow-ups.

Verification:

- After `npm run build:site`, all 998 devlogs HTML files contain the noindex meta tag.
- `public/sitemap.xml` (3630 URLs) contains no `/devlogs/` URLs.
- `npm run lint:seo` exits 0.
- No IDE diagnostics on the edited files.

## Notes / boundaries

- Deploying needs `build:site`, `upload:r2`, and `git:deploy`. Nothing was deployed in this session.
- Do not add the robots Disallow until Search Console shows devlogs excluded by noindex.
- The audit is structural, not a SERP comparison. Bucket B work still needs per-slug SERP checks, verifiable additions, and independent rewrites in all 10 locales. It should go in batches of at most 10.
- Copy hard-coded in `*Page.ts` outside the i18n keys is not counted, so a few tools may score thinner than they are.
