# 03 — 哪些是增强功能（相对网站）

**目的**：插件不是把 `*Page.ts` 塞进 popup。没有「当前标签页 / 右键 / 多标签」增量的能力，用户不会装，审核也会问「这和网站有什么不同」。

分层：

| 层 | 定义 | 例 |
|---|---|---|
| **增强（必须先做）** | 网站技术上做不到，或做得很差 | 把**已登录、已渲染**的当前页存成 PDF |
| **顺手增强** | 网站能做，但插件少一步 | 右键图片压缩，不必另开标签上传 |
| **对等（可后做）** | 和网站同一作业，只是换壳 | popup 里合并两个本地 PDF |
| **不要做** | 插件更差或政策风险 | 在扩展里跑 Turnstile AI；劫持新标签页 |

## 1. E1 PDF：增强 vs 对等

### 必须先做的增强（这是 E1 存在的理由）

站点 `batch-convert-web-pages-to-pdf` 的已知边界（见该工具 `02-tool-info`）：

- 公开 URL 要 **Worker 代抓一次**
- **登录墙 / 私网** 失败
- 重度 JS 应用、打印 CSS 可能不像用户看见的那样

插件可以：

1. **Save this tab as PDF**  
   对用户正在看的文档跑 html2pdf / print 媒体（`document` 已有 cookie、SPA 已 hydrate）。这是网站代抓做不到的。
2. **Save selected tabs**  
   用户勾选已打开的帮助中心标签，生成多 PDF + ZIP。比「再把 URL 贴进网页工具」少一整步，且带着登录态。
3. **Right-click → Save as PDF**  
   减少「找到本站 → 粘贴 URL」的漏斗。
4. **等待图片 / 懒加载后再打**（可选增强）  
   滚动到底或等 `load`；网站代抓很难稳定做到。
5. **只保存所选 DOM**（可选）  
   用户划选文章主体，去掉导航/cookie 墙。网站没有「当前页选区」。

### 顺手增强

- 右键 **PDF 链接** → 下载后立刻压缩/合并（仍要处理跨域失败）。
- 把刚保存的多个 PDF 一键合并（工作流粘合，仍属 PDF 用途）。

### 对等（v1 可以少做，v1.5 再齐）

合并、拆分、压缩、水印：用户本来就会打开 `/tools/merge-pdf`。插件价值是「不用离开当前任务」。可以做，但 **不要**作为商店主图和标题唯一卖点——标题要落在 *save page as PDF* 这类商店检索句。

### 不要假装增强

- 在后台静默把用户访问过的每个 URL 都生成 PDF（监视、耗电、政策）。
- 整站爬虫（与站点红线一致：上限、无爬虫）。

## 2. E2 Image：增强 vs 对等

### 增强

1. **右键 `<img>` → 压缩 / 转 WebP / 去 EXIF**  
   电商/社交运营在 Instagram 后台就能处理，不必下载再打开网站。
2. **右键 → 按平台裁切**（Story 1080×1920 等）  
   站点已有尺寸工具；插件把「当前这张图」送进同一套编码器。
3. **拖一张图到工具栏按钮**（若 UX 允许）  
   比打开网站少一次导航。

### 对等

popup 里选文件批量转码 = 网站 bulk 工具。作为核心功能的补充，不要当唯一卖点。

### 边界（要在 UI 写清）

- 热图 / 画布 / CSS background 不一定能当 `img` 右键；失败时引导「拖文件进来」。
- 跨域 `src` 可能被 canvas 污染；不要申请过宽 host 权限去绕。

## 3. E3 Inspector：增强 vs 对等

### 增强（E3 的理由）

站点检查器多数是「粘贴 URL 或 HTML」。插件可以：

1. **一键审计当前 DOM**（真实 title/H1/canonical，含 SPA 写进去的）
2. **看见用户已登录的预览页** 的 OG（代抓往往是登录墙 HTML）
3. **点选页面两个颜色做 WCAG**（比在工具里填 HEX 快）
4. **从当前 URL 预填 UTM / hreflang 草稿**

### 对等 / 诚实限制

- 完整重定向链、CDN 头：标签页里不一定能看到服务器原头；可 **可选** 走现有 `website-headers` Worker，并在 UI 标明「边缘看到的头」。
- Core Web Vitals：扩展读到的是这一次加载，不是 CrUX。站点工具已经是「粘贴 Lighthouse 数字」——插件不要假装自己是 PageSpeed。

## 4. 所有插件共用的产品规则

1. **默认本地**：与首页「不上传」标签同一承诺；远程只在用户明确点「用服务器看头 / 拉 robots」。
2. **深链回网站**：popup 底部「在网站打开完整说明 / FAQ / 十语文档」。这是 SEO 与信任，不是把插件做成 iframe 套壳。
3. **禁止** 为了装机量改主页搜索、插广告、强制新标签（政策 + 卸载率双杀）。
4. **增强功能必须出现在商店前两张截图**。对等功能放后面。

## 5. 验收一句话（每个版本都问）

> 关掉网站，只装插件，用户能否完成一件 **离开网页工具就做不到或很难做** 的事？

- E1：已登录的后台页 → PDF。能 = 增强成立。  
- E2：Instagram 里右键压图。能 = 增强成立。  
- E3：SPA 预览页一键 OG。能 = 增强成立。  
- 若只能「在小窗里再选一次文件」= 对等，不能当首发卖点。
