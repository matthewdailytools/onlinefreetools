# 挽救策略（2026-10-13）

前提：全站近清零 + 10/6 断崖 → 按 **自动化 spam（偏 scaled content）** 做恢复，目标是让系统在数月内重新评估「本站不是主要为操纵排名的铺量站」。

官方要点：违规站可排名下降或几乎不出现；**改正后可能需数月**才被自动化系统重新学习；**没有**针对自动化 spam 更新的「请求重新审核」。

## 0. 先确认边界（1 天内）

1. GSC → **人工处置**：若有条目，走该条的「请求审核」；若无，全程按自动化处理。
2. 网址检查抽 5 条：首页、仍有零散曝光的工具、已死的计算器、prompt、PDF 各一 → 看「是否在索引」与实时抓取是否 200。
3. Cloudflare Analytics：10/6 前后请求量是否同步腰斩（分清「没人来」vs「来了但搜索没展示」）。

## 1. 止血：立刻停止继续像 spam

| 做 | 不做 |
|---|---|
| **冻结**新 `how-to-calculate-*`、新 prompt builder 变体、近义 PDF/batch 长尾拆页 | 为「救流量」再批量上新薄工具 |
| **冻结**为凑收录而刷 IndexNow / 批量「请求编入索引」 | 买外链、PBN、互暖、刷提及 |
| 周建工具若要做：只做 **唯一作业 + 满 IG**，且 ≤1 | 用 AI 一夜重写两千 URL「换皮」 |
| 保持 robots 可抓、勿全站 noindex | 恐慌性 `Disallow: /` 或全站 noindex |

## 2. 降表面积：动同构簇，不动十语骨架

原则：**十语保留**；砍的是「同构工具 URL」，不是语言。

### P0 — 计算器 how-to 族（约 60）

优先处理：模板最同、FAQ 最薄、对「铺量」贡献最大。

可选路径（按激进程度）：

1. **收敛（推荐先做）**：按主题合并进少量 hub（面积 / 体积 / 速度…），子公式用页内模式或锚点；多余 slug **301 → hub** 或逐步 `noindex` 后删。
2. **软降权**：短期对最薄计算器加 `noindex,follow`，保留产品入口但退出争夺索引（须产品同意）。
3. **硬砍**：直接下线无流量、无书签依赖的薄页（破坏性最大，适合确认无用户资产后）。

### P1 — prompt builder 族

合并为 **1 个通用 Prompt template builder + 少量真有字段差分的场景**；其余 301/noindex。消灭「FAQ 同壳只换场景名」。

### P2 — PDF / batch-convert 兄弟姐妹

**保留**真实功能差分页（JPG vs PNG vs PDF 输出不同）；删/并的是 **仅换词、无交互差分** 的长尾。Related 链指向规范页，勿再裂变。

## 3. 加固幸存者：让「零散曝光」变成锚点

从 GSC 仍有展示/点击的 URL 与站内旗舰工具（如 text-diff、真本地 PDF 作业、独特转换器）入手：

- 补 **可验证 IG**：边界、失败态、示例、与兄弟工具的「何时不要用」。
- 加强内链：首页 / topic hub → 幸存者；弱化指向将被收敛的薄页。
- About / 隐私已诚实；保持 people-first，勿写「我们被惩罚了」类站内文案。

目标：系统重新抽样时，看到的是 **少量高差分工具站**，不是 **两千近模板 URL**。

## 4. 预期与节奏

| 阶段 | 时间 | 成功信号 |
|---|---|---|
| 止血 + 抽查 | 本周 | 人工处置明确；停建薄簇 |
| 收敛 P0/P1 | 2–6 周 | 可索引工具 URL 明显下降；hub 可抓 |
| 等待重评估 | **数月** | 展示从「零散」缓慢回升；非一周内回到 10/5 水平 |
| 复盘 | 每 2–4 周 | 导出 Dates + 网页，看簇是否先于全站回暖 |

**现实**：全站近清零后，即使改对，也常见 **数月** 才明显回升；期间可能只有零散曝光。不要用「再铺 50 个长尾」赌短期回血。

## 5. 决策门

- **禁止**为恢复排名而新增 doorway / 近义 URL。  
- **允许**合并、301、对薄簇 noindex、强化幸存者。  
- **冲突时**以 Google Search Central spam policies 与仓库 `seo-google-policy.mdc` 为准。
