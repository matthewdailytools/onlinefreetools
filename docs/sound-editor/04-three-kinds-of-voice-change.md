# 04 — 三种变声详解

**日期**：2026-09-09  
**状态**：说明文档（对人可读）；实现栈见 [03](./03-voice-conversion-from-speaker-samples.md)  
**一句话**：变声不是一种算法。先分清改的是 **音高玩具**、**音色涂层**，还是 **为某人训一台声带**。

---

## 0. 人声里其实有三层

听一段说话，耳朵同时收到：

| 层 | 是什么 | 日常说法 |
|---|---|---|
| **内容** | 音素、字、词 | 「他说了什么」 |
| **韵律** | 音高曲线、快慢、停顿 | 「语气、抑扬」 |
| **音色 / 声纹** | 声道共鸣、气息、个人特色 | 「听着像谁」 |

三种变声动的层不一样。混在一起就会拿升调去「克隆某人」，或指望一批 wav 在浏览器里训出 RVC。

```
V0  DSP 变调     → 主要拧「韵律里的音高」，音色跟着变形，人还是你
V1  音色迁移     → 尽量保住内容和节奏，把「像谁」往参考人身上推
V2  训练式克隆   → 用大量某人录音，学一台只属于他的发声器，再拿来唱/说
```

---

## 1. V0 — DSP 变声（信号处理，不要目标人）

### 1.1 在干什么

把 **这一段已经录好的波形** 用滤波器、变速、移调算法改掉。  
不认识「张三」「李四」，也 **用不到** 那个人的一批录音。你把张三的参考丢进去，算法当普通 PCM 处理，不会因此更像张三。

典型听感：

- 升高：松鼠、童声卡通  
- 降低：巨人、慢放电影  
- 电话：窄带 EQ  
- 机器人：声码器、环调、比特粉碎  

**人还是源说话人**，只是被拧过。熟人听 5 秒通常仍能认出是你在玩效果。

### 1.2 常见做法（由假到稍正经）

**A. `playbackRate`（不要当变声产品）**

播放加快则音高升高、时长变短。像磁带加速。导出若只改播放速度，文件时长也对不上口型。这是预览玩具，不是变声器。

**B. 移调、时长不变（SoundTouch 等）**

时间域拼接或相位声码器：音高变、句子长度基本不变。  
问题：声道共鸣（**共振峰 formant**）会跟着音高跑。升五度 = 典型「松鼠」；降很多 = 「巨人」。  
这是 **故意的卡通变声** 时要用的模式（`formantStrength = 0`）。

**C. 移调 + 保住共振峰（LPC / 倒谱包络）**

先估计声道包络，移调后再把原包络盖回去。听感更像「同一个人口型唱高了/低了」，而不是换了一个人。  
库：`@soundtouchjs/formant-correction-worklet`（LPC）、`@audio/shift-formant`。  
**仍然没有目标说话人**。保的是 **源** 的声道，不是张三的声道。

**D. 延迟链「氦气」效果（Jungle 一类）**

几路不同延时的梳状滤波，经典 Web Audio demo。假、便宜、好玩，不像任何人。

### 1.3 输入 / 输出 / JS

- 输入：一段源音频（或麦克风实时）  
- 输出：同样内容的扭曲版  
- JS：Web Audio + AudioWorklet；导出用 `processOffline()` 或 `OfflineAudioContext`  
- 体积：几十到几百 KB 级库，适合进波形编辑器菜单  

### 1.4 什么时候用 V0

铃声玩笑、直播搞怪、配音「非人」角色、编辑器里的 Pitch 旋钮。  
**不要**用 V0 回答「根据一批某人的声音变成他」。

## 2. V1 — 音色迁移（参考声纹涂层）

### 2.1 在干什么

需要 **两份音频**：

1. **源（source）**：决定「说了哪句话、什么节奏」（内容和韵律基本来自这里）  
2. **参考（reference）**：目标人的声音，一段或多段。算法抽出「他听起来像谁」，涂到源上  

结果：口型/词还是源的，音色往目标人靠。像给源语音换了一层「声道油漆」，不是让模型从零学会那个人怎么说话。

所以用户说的「一系列个人的声音」在 V1 里是 **参考集**，用来稳定那个油漆颜色（embedding），不是拿去训练神经网络权重。

### 2.2 内部在算什么（不必会公式也能懂）

1. 把波形做成短时频谱（STFT）：每一小窗是一张「声音的瞬时谱」。  
2. **参考编码器** 把谱压成一个短向量（OpenVoice V2 浏览器实践里是 **256 维**），叫 speaker embedding / 音色向量。  
3. 多段参考 → 多个向量 → **加权平均**（长的、响的人声权重大）→ 一个目标向量。  
4. 源音频也得到源向量 + 源谱。  
5. **转换器** 吃：源谱、源向量、目标向量（外加一点噪声），吐出新波形。  

转换器在学的是：「在保持源的语言内容的前提下，把谱的说话人相关部分换成目标向量所代表的音色。」  
它 **没有** 为张三单独开一套上亿参数的专属模型；张三只是 256 个数。

### 2.3 为什么要「一系列」而不是一段

一段 3 秒可能含咳嗽、房间混响、偶然偏高。多段平均能把噪声方向抵消一点，音色更稳。  
这 **不是** 「数据越多越像 RVC」：V1 的模型权重是 **固定的通用转换器**，你再丢 1 小时参考也只是把那 256 维估得更稳，不会长出新网络。

### 2.4 做不到什么

- 不会从文字长出语音（那是 TTS；V1 只转 **已经存在的说话**）。  
- 只有参考、没有源 → 没有「那句话」可涂。  
- 不像度通常低于为该人训过的 RVC；口音、情绪、设备差会露馅。  
- 参考必须是干净人声；BGM/合唱会把 embedding 拉脏。

### 2.5 JS 现实路径

OpenVoice V2 拆分 ONNX：encoder ~1.6 MB + converter ~64 MB。  
`onnxruntime-web`，Converter 优先 WebGPU，Worker 里跑，点击后加载。详见 [03](./03-voice-conversion-from-speaker-samples.md)。

### 2.6 什么时候用 V1

「我有自己的几段录音，想让另一段旁白听起来像我」；「有授权的配音参考，转一段已有台词」。  
浏览器工具页 **默认该打 V1**，不要承诺证件照级克隆。

## 3. V2 — 训练式克隆（RVC 等）

### 3.1 在干什么

分两步，千万不要合成一步：

**训练（train）**  
用目标人 **大量干净语音**（社区经验大约 **10–50 分钟**，音色一致、底噪低）在 GPU 上跑很多轮。  
得到一个 **只属于这个人的检查点**（常见 `.pth`，约 60+ MB 的可分享推理包，不是日志里几百 MB 的实验存档）。

**推理（infer）**  
再拿 **任意源音频**（你唱的歌、你说的话）进这个检查点：内容编码器抽出「唱了什么」，说话人部分用训好的人，合成像他的声音。  
像度通常高于 V1，尤其唱歌；代价是必须先有模型。

Retrieval-based Voice Conversion（RVC）还会用特征检索（index）混一点训练集里的相近帧，进一步贴目标人。

### 3.2 和 V1 的本质差别

| | V1 音色迁移 | V2 RVC |
|---|---|---|
| 目标人存在哪 | 一个 256 维向量（当场从参考算） | 一整份网络权重（事先训好几小时 GPU） |
| 「一系列 wav」的作用 | 平均 embedding | **训练集**（切特征、跑 epoch） |
| 当场只有 5 段 10 秒 | 可以开始转 | **不够训**；硬训会过拟合或崩 |
| 浏览器 JS | 推理通用 ONNX，适合工具页 | 训练不行；推理要用户 **自带模型** + HuBERT/RMVPE 等 |

### 3.3 为什么工具页不能「丢一批 wav 点一下训出 RVC」

- 要抽 f0（音高）、内容特征（HuBERT/ContentVec），再反向传播更新上千万参数。  
- 时间：消费级 GPU 也是许多分钟到数小时，不是一次 `decodeAudioData`。数量级见 [07](./07-voice-clone-training-cost.md)。  
- 内存与 WASM：浏览器标签页扛不住完整训练图。  
- 数据：10–50 分钟干净一致人声，用户随手录的「一系列手机备忘」通常不合格。

浏览器里 **能** 做的 V2 子集：用户已经有 `.pth`/`.onnx`，用 `rvc-web-runtime` 一类做 **推理**（还要额外内容/音高模型，体积再加一截，常要 COOP/COEP）。  
`.pth` → `.onnx` 也可在浏览器转（`rvc-onnx-web`），那只是格式，不是训练。

### 3.4 什么时候用 V2

自己做模型、或用户带来已授权的模型做唱歌/变声。  
本站默认 **不托管、不训练、不提供名人模型**。

## 4. 对照总表

| 维度 | V0 DSP | V1 音色迁移 | V2 RVC 训练+推理 |
|---|---|---|---|
| 要目标人录音吗 | 否 | **要**（数秒到数分钟参考） | **要**（训练用 10–50 分钟；推理用模型） |
| 改哪一层 | 音高/滤波，音色扭曲 | 说话人音色 | 整台目标发声器 |
| 还像源说话人吗 | **像**（熟人能认） | 内容像源，音色像目标（有限） | 尽量像目标 |
| 有「说的那句话」吗 | 源本身 | **必须另有源** | 推理时必须有源 |
| JS 工具页 | 轻，进编辑器 | 中：~66 MB ONNX | 训练否；推理重且要自带模型 |
| 典型库 | SoundTouch、Web Audio | OpenVoice ONNX | RVC WebUI / rvc-web-runtime |
| 本站产品落点 | 波形编辑器效果 | 独立 slug（未立项） | 默认不做训练 |

## 5. 用场景选档（避免买错）

- 「让我的声音听着滑稽」→ **V0**  
- 「这句旁白用我自己另外几段录音的音色」→ **V1**  
- 「用我练了半小时的模型去翻唱」→ **V2 推理**（模型在训练阶段已完成）  
- 「只上传某人一堆 mp3，没有要转换的句子，也没有模型」→ 哪一档都不完整：缺源则 V1/V2 推理无法开始；缺训练则 V2 不存在  

---

## 6. 合规（三档都适用）

只处理用户有权使用的声音。V1/V2 尤其容易被理解成「克隆别人」。产品文案写授权与反欺诈，不提供名人音色包。
