# 06 — 需求 × 难度 × 成本：分层与开发节奏

**日期**：2026-09-09  
**状态**：规划文档；**不是**立项、未改 `src/`  
**输入**：[05 需求全景](./05-sound-universe-demand-map.md)  
**本站编辑器（01/02，第十二轮）**：W0 网页编辑器改为 **vendor AudioMass 整树**，不再从零做 EDL；本篇其余波次仍是「声音应用宇宙」，不要把 copy 理解成 05 的生成/仿声也一并做了。  
**本篇做什么**：把 05 的枚举收成 **可排序的能力包**，按用户需求、技术难度、实现成本分层，并给出 **开发波次**。  
**本篇不做什么**：不按本站「免费网页工具」裁范围；不绑定必须用 JS；不给精确人月承诺。明星仿声等敏感项 **排序时计入合规成本**，不是直接开做。

技术分型仍以 [03](./03-voice-conversion-from-speaker-samples.md) / [04](./04-three-kinds-of-voice-change.md) 为准：V0 DSP ≠ V1 迁移 ≠ V2 训练克隆。

---

## 0. 怎么打分

单位是 **能力包**（用户能感知的一块作业），不是 05 里每一条命令。同一包里的按钮可以随波次加厚。

| 维 | 1 | 3 | 5 |
|---|---|---|---|
| **需求 D** | 长尾、偶发 | 垂直刚需或周频 | 大众日频，或创作者周频且愿意付钱 |
| **技术难度 T** | 成熟 DSP / CRUD | 要接模型或认真做音频工程 | 实时、训练、空间、硬实时路由 |
| **实现成本 C** | 数周可出荷 | 一季：工程+少量算力或授权 | 内容采购、GPU 常开、法务、持续标注 |

**成本 C 包含**：研发人时、推理/API 账单、素材与音乐授权、审核与法务、客服与失败案例。只算写代码会把「内容库」「仿声」估得过便宜。

**分层规则**（先定性，表内数字是辅助）：

| 层 | 含义 | 经验式 |
|---|---|---|
| **L0 地基** | 没有就不是「以 editor 为入口的应用」 | 工作台本身 |
| **L1 高性价比闭环** | D≥4 且 max(T,C)≤3；或六跳里最便宜的真下一跳 | 先做 |
| **L2 差异化** | D≥4 且 max(T,C)≥4；模型或授权换质量 | 地基稳了再砸 |
| **L3 加厚 / 垂直** | D=3，或强依赖 L2 | 有主路径再包皮肤 |
| **L4 缓做 / 默认不做** | D≤2，或合规风险压过需求 | 记录需求，不进节奏主链 |

**买 vs 造（贯穿所有波次）**

| 造（自己做产品与时间线） | 第一年默认买或开源推理 | 先法务后技术 |
|---|---|---|
| **本站网页编辑器**：整树 vendor [AudioMass](https://github.com/pkalogiros/audiomass)（MIT）+ 十语/HUD/隔离；DSP 变声、响度、两轨随上游带上；库的交互 | STT、TTS、分轨、文生乐、文生音效 | 未授权明星/公众人物、已故者、医疗诊断 |

节奏按 **波次** 排，不绑日历。文中「一波」粗量：**4–8 人全职（产品+设计+工程）约 6–10 周**。人少就拉长，不要跳波次把 L2 塞进 L0。

## 1. 总原则（比分数更重要）

1. **先工作台，后魔法。** 生成/分轨/TTS 若无处可改、无处可听，会变成一次性下载器，应用长不出来。  
2. **六跳各先做最便宜的真版本**，再加深。见 [05 §23](./05-sound-universe-demand-map.md)：修好 / 换身份 / 拆开 / 补上 / 看懂 / 发出去。  
3. **用户点名的五块都要进主链，但不是同一波。** 编辑 → 库与 DSP 变声 → TTS 进时间线 → 自己的声音 → **授权后的** 音乐仿唱。  
4. **日活入口可以第二条：实时变声/音板。** 它需求极高、工程也硬，故 **L2、W4**，不要当 W0。  
5. **内容库的瓶颈是授权与编目，不是播放器。** 工程上可与 W0 并行开工（采购、元数据），产品上 W1 才挂进编辑器。  
6. **仿声拆三档交付**：玩具滤镜（V0）→ 授权克隆自己（V1/TTS）→ 明星/AI Cover（法务门闸）。混在一波会又慢又险。

## 3. 分层一览

### L0 — 地基（W0）

没有这些，后面所有模块都是外链工具，不是一个应用。

- 打开、波形、剪贴撤销、淡化、录音、导出  
- 工程心智：时间线是唯一工作台（TTS/库/变声都写回这里）  
- **若走本站网页编辑器（01/02）**：上述能力用 AudioMass MIT 整树 vendor，不要按「自研 EDL 人月」估 W0

### L1 — 高性价比闭环（W1–W2）

用户点名五块里，**先落地的不是最酷的那块**，而是能完成六跳的便宜真功能：

| 六跳 | L1 真版本（必须能点、能听、能导出） |
|---|---|
| 修好 | 降噪 + LUFS |
| 换身份 | V0 滤镜包（明确告诉用户：这不是克隆某人） |
| 拆开 | 人声/伴奏两分（W2） |
| 补上 | 种子库拖入；TTS 进轨（W2） |
| 看懂 | STT + 字幕 + 按句选区（W2） |
| 发出去 | 铃声/格式；Audiogram（W2） |

另加：**睡眠声景** 作为第二条轻入口（可几乎不碰精剪），用同一套库。

### L2 — 差异化（W3–W5）

这里才开始像「声音操作系统」，也才开始烧钱。

- 自己的声音 → TTS / V1 迁移  
- 文生 BGM / 音效、续长  
- 实时变声入口  
- 视频配音闭环  
- **授权** Cover 与角色市场  
- 水印与合成检测  

### L3 — 加厚（W5–W6）

播客/有声书/语言学习等 **套件**、4 轨、扒带、识曲合作。不抢 L0–L2 的人。

### L4 — 不进主节奏

未授权仿声、医疗诊断、偷录、自建识曲指纹网、自训基础大模型。文档里保留需求，排期表写 **禁/缓**。

## 4. 用户点名五块：单独排序

避免「五块并列第一年」。

| 顺序 | 块 | 第一年怎么切 | 层 / 波次 |
|---|---|---|---|
| 1 | **声音编辑** | 完整单轨 → 两轨闪避；效果可预览 | L0 → L1，W0–W2 |
| 2 | **声音内容库** | 先可商用种子包 + 检索拖入，再生 | L1，采购并行 W0，上架 W1 |
| 3 | **AI 变声** | 先 V0 滤镜；再 V1/自己的声音；实时最后 | L1 W1 → L2 W3 → 实时 W4 |
| 4 | **TTS** | 现成音色进时间线 → 克隆自己 → 多角色有声书 | L1 W2 → L2 W3 → L3 W5 |
| 5 | **明星 / 音乐仿声** | **先做分离+修音+授权框架**；Cover 本体 W5；未授权永不排 | L2 W5 / L4 |

「仿声」若在 W1 用升调冒充，会透支信任，后面真克隆也难卖。W1 必须把 V0 的产品文案写诚实。

## 5. 开发节奏（波次）

```
时间 →

W0  工作台 ████████
      库采购 / 元数据 ████████████        （内容组并行，不堵工程）
W1  修好 + V0变声 + 种子库 + 格式/铃声 ████████
W2  两轨闪避 + 人声分离 + STT字幕 + TTS进轨 + 声景 ████████
W3  克隆自己 + V1迁移 + 文生补全 + 去嗯啊     ████████
W4  实时变声/音板 + 视频发出去 + 修音/母带    ████████
W5  授权 Cover/音色市场 + 检测水印 + 套件皮肤 ████████
W6  平台化、4轨封顶、识曲合作、空间/MIDI 选做 ████
```

每波 **出口标准**（没达到不要开下一波的 L2）：

| 波次 | 用户可完成的一句话作业 | 出口标准 |
|---|---|---|
| **W0** | 「打开或录一段，剪掉废的，导出干净文件」 | 撤销可靠；立体声；导出无水印；关掉标签页工程可提示保存（本地即可） |
| **W1** | 「难听的人声能修好；能玩变声滤镜；能从库拖一声雷进轨」 | 降噪可 A/B；V0 滤镜 ≥8 个听得懂的名字；库 ≥ 三类（人/动物/自然）且许可标注清楚 |
| **W2** | 「口播加垫乐；卡拉 OK 出伴奏；文稿出声进时间线；录音出字幕」 | 六跳每类至少一个 **非灰** 入口；TTS 不是外链 |
| **W3** | 「用我的声音读稿；用字生成缺的音效/BGM；删掉嗯啊」 | 克隆有同意流与撤销授权；生成结果可再剪 |
| **W4** | 「直播里实时变声；口播配到视频导出」 | 实时延迟可接受（目标交互级，游戏级另标）；视频路径有一种主格式 |
| **W5** | 「在授权范围内换歌手/角色；平台能标合成」 | 无授权曲/声则拒绝，而不是降质偷跑 |
| **W6** | 「团队审听、外部 API、垂直壳」 | 有账号与权限才做；否则停在单人应用 |

### 5.1 并行轨道（否则内容与法务永远落后）

| 轨道 | 从哪波开工 | 谁 |
|---|---|---|
| A 编辑与 DSP | W0 | 音频工程 |
| B 模型接入（推理/API 网关、账单、失败回退） | W2 | 后端 |
| C 内容与授权（库、BGM、音色合同） | W0 起 | 内容+法务 |
| D 信任（同意、水印、滥用审核、儿童） | W3 起必须有人 | 法务+安全 |
| E 实时客户端（驱动/虚拟声卡） | W3 预研，W4 出荷 | 客户端，避免用网页硬扛 |

### 5.2 每波刻意 **不** 做的（防膨胀）

| 波次 | 禁止塞进来的 |
|---|---|
| W0 | 任何云端大模型、多轨 DAW、插件市场 |
| W1 | 克隆某人、Cover、实时、自研降噪 SOTA |
| W2 | 明星音色、自建 STT 训练、Atmos |
| W3 | 未授权名人、开放音色上传无审核 |
| W4 | 完整 MIDI 制作线、工业检测 |
| W5+ | 把 L4 项「先做着玩」 |

## 6. 若资源极紧：最小节奏（仍像一个应用）

假设只有 **很小的团队**，不能按 4–8 人波次走。砍的是深度，不是六跳：

| 顺序 | 做 | 明确砍成 |
|---|---|---|
| 1 | W0 编辑器合格线 | 不要只做裁剪器（与 02 一致） |
| 2 | W1：降噪 + V0 变声 + **小**种子库（哪怕每类 30 条许可清晰的） | 库宁缺毋滥 |
| 3 | W2 里三选二：**分离** / **STT** / **TTS 进轨** | 另外一个做灰入口「即将」 |
| 4 | 再碰 W3 克隆自己 | 全程同意 |

不要为了「有 AI」跳过 1–2 去做 Cover。需求上 Cover 最大，成本和风险也最大，小团队会在法务和算力上同时死。

## 7. 风险如何改排序（分数修正）

| 现象 | 对层的修正 |
|---|---|
| 未授权名人 D=5 | **不升到 L1**；锁 L4 |
| 内容库 T=2 但授权未谈妥 | C 视为 5，W1 只上已清权利的包 |
| STT/TTS API 可买 | T 从 5 降到 3，故能进 W2 |
| 实时变声在网页 | T 保持 5；改原生后再承诺游戏场景 |
| 睡眠声景 D=5、T=2 | 可 W1 做独立简单页，但素材与编辑器同源，避免两套资产 |

## 8. 和 01–02 浏览器编辑器的关系

- **01–02** 描述的是本站网页编辑器的合格线，大约落在本篇 **W0 + W1 的 DSP/响度/降噪**，**不含** W2 起的分离/TTS/STT（02 曾列为「本 slug 不做」）。  
- **本篇** 排的是「声音应用」主链。若某一天只做本站一页，就 **只执行 W0–W1 里能在浏览器诚实交付的子集**，不要假装 W3 克隆已排进该 slug。  
- 两套镜头仍然分开：05 不管实现；06 引入 T/C；01–02 才是本站页范围。  
- 仿声训练的 GPU / 人时 / 数据拆账见 [07](./07-voice-clone-training-cost.md)。

## 9. 结论

- 排序不是「需求高就先做」。明星仿唱、识曲、实时变声都是高 D，但分别被 **法务、数据护城河、系统延迟** 挡住。  
- 正确顺序：**工作台 → 修好+V0身份+种子库 → 拆开/看懂/TTS → 自己的声音与生成 → 实时与视频 → 授权仿唱与信任设施。**  
- 用户点名五块全部在主链上，落地顺序是 **编辑、库、变声（先 V0）、TTS、仿声（最后且要授权）**。  
- L4 项继续留在 05 当需求事实，不进入开发波次。

下一步若要再收：按某一波写能力清单（验收用例），或把 W0 映射回 `work-tasks/`——须用户明确点名。
