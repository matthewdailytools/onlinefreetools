# 背景和新架构需求

由于 cloudflare免费有3M的构建包硬性要求，所以解决方案是将多语言生成页面存放于R2，worker处理动态请求和协调语言，静态文件存放于asset

基于 **Cloudflare Workers + R2 ** 的三层缓存架构。R2 存放生成的 HTML 页面（统一以 gzip 压缩形式存储单版本），先边缘CDN缓存，然后Worker 作为统一入口按「Cache API 检查 CDN 缓存 → R2 存储」三层缓存架构处理请求，并根据请求头 `Accept-Encoding` 返回对应编码：gzip 客户端直接获得预压缩数据，不支持 gzip 的客户端经解压返回，实现边缘加速。

可执行设计、键规范与发版步骤见 [design.md](./design.md)。


## 架构概览

```
浏览器请求
   │
   ▼
边缘CDN缓存
┌──────────────────────────────────────────────────────┐
│ Worker 统一入口                              │
│  第一层：worker + Cache API 检查 CDN 缓存  → 命中直接返回          │
│  第二层：worker + R2 存储桶读取 gzip HTML              │
│  第三层：API worker处理动态请求（例如需要服务器处理的 ip address 工具等） │
│                                                      │
│  内容协商：按 Accept-Encoding 返回                        │
│            gzip 预压缩数据或解压后的未压缩内容             │
└──────────────────────────────────────────────────────┘
```
