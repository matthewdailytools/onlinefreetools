工具方向 — JS 能力 × AI 桥接 × 行业专属

日期: 2026-07-28
标签: 产品规划, 工具方向, AI桥接, 行业工具
目标站点: https://onlinefreetools.org

关联文档:

  • JS 工具包调研 — npm/浏览器包选型附录（保留包表，不重复梯队优先级）
  • 工具页 SEO 与 Information Gain — 页面怎么赢 Google
  • 工具页面 SEO 规则 — description / FAQ 硬规则
  • 音视频可行性 — 多媒体 WASM 约束
  • 工具目录源：src/site/tool-catalog.json

本文职责：回答「做什么工具、不做什么」。页面 SEO / Information Gain 见姊妹文档。

1. 核心定位

不做泛化工具超市。 按 可落地 JS 能力 × AI 生态桥接 × 行业场景 立项。

要做 不做
有明确行业任务或 AI 流水线环节的转换 / 校验 / 解释工具 无行业语境的「又一个单位换算 / 又一个密码生成器」空壳
浏览器本地或边缘可完成的格式桥接 AI 写作付费墙、站群式工具超市
能写出公式、规则、边界与权威出处的真工具 仅为长尾词批量复制的变体页

相对竞品启示（压缩）：竞品靠数量铺量；本站靠 多语言 + 教育式说明 + 本地隐私 + 行业/AI 语境 建立差异，而不是堆计算器变体。

2. 红线

  1. 空壳变体页 — 如 5 个仅 slug/title 不同的面积计算器；违反 spam / 信息增益红线。
  2. 无增量机翻堆页 — 10 语言须人工审核后再上线。
  3. 纯为词而建的泛化工具 — 搜索量高但无行业/AI 语境、无法写出增量说明 → 不立项。
  4. 偏离定位的重后端能力 — 抄袭检测、完整视频转码站、国家专属报税等（成本/合规/CWV 不匹配）。
  5. 把「开发者底座」当超市入口 — JSON / Base64 等仅在能服务 AI 流水线或行业数据交换 时立项，不作为铺量清单。

3. 能力底座（引用包调研）

技术可行性与包枚举以 JS 工具包调研 为准。产品侧只遵守：

3.1 选型优先级

  1. 零依赖 / 极小体积（原生 API 优先）
  2. Tree-shakeable、同构可用（浏览器 + Workers）
  3. WASM / 大模型 用户触发后再 import()
  4. 可写出 SEO 可描述的输入 → 规则 → 输出
  5. 安全默认值（DOMPurify、演示级加密声明、本地处理声明）

3.2 加载分层

层级 体积 时机 示例
Tier 0 零依赖内联 页面打开 JSON 校验、Base64、Token 粗估、零宽字符清理
Tier 1 < 200KB 动态 import 打开或首次交互 js-yaml、papaparse、qrcode、zod
Tier 2 > 1MB WASM/模型 点击后再加载 FFmpeg、Tesseract、Transformers.js

音视频细节见 音视频可行性。

4. 方向一：AI 桥接转换工具

定义：服务 LLM / Agent / 多模态流水线中的 格式、校验、转换、计量、安全粘贴，不做「替用户写文案」的生成产品。

工具方向 用户任务 推荐技术 可写清的规则/公式 建议 slug
Token / 字符与成本估算 粘贴 Prompt/对话，估 token 与费用 字符启发式或轻量 tokenizer；价格表可配置 估算公式、模型价差、局限说明 ai-token-counter
对话导出互转 ChatGPT/Claude 导出 ↔ Markdown / JSON / CSV 纯 JS 解析 + papaparse 字段映射表、丢失字段说明 chat-export-converter
Prompt 模板结构化 自由文本 → 角色/任务/约束/输出格式 规则拆分 + 可选 zod 模板字段定义与示例 prompt-template-builder
JSON Schema 校验 校验模型输出是否符合 Schema zod / Ajv 浏览器版 Schema 规则 + 错误路径解释 json-schema-validator
Embedding 相似度演示 两段向量余弦相似度 + 维度说明 纯数学 余弦公式、归一化注意 embedding-cosine
OCR → 结构化文本 截图/扫描件 → 可复制文本 tesseract.js（Tier 2） 语言包、准确率局限、本地处理 ocr-to-text
安全粘贴 / 隐藏指令清理 去掉零宽字符、隐藏 prompt 注入痕迹 纯 JS Unicode 过滤 检测规则表 + 前后对比 safe-paste-cleaner
YAML/CSV ↔ JSON（AI 数据） 训练/配置数据格式互转 js-yaml、papaparse 类型推断规则、示例文件 yaml-json / csv-json

边界：

  • 可做：解释「为什么校验失败」、对比 tokenizer 差异、本地 OCR。
  • 不做：托管大模型推理付费墙、批量 AI 文章生成、伪装成「AI SEO 专用」的空壳页。

5. 方向二：行业专属工具（非泛化）

每个工具必须同时具备：行业痛点任务 + 领域术语 + 标准/规范引用（能写进 References）。禁止「通用计算器换皮」。

5.1 首批垂直（默认）

行业 痛点任务 示例工具 包/技术来源 SEO 意图词（例） YMYL
开发者 / 数据交换 API 与配置格式互通、Headers 调试 JSON Schema 校验、Markdown↔HTML、YAML↔JSON、Website Headers（已有） zod、marked/turndown、js-yaml json schema validator, yaml to json 否
内容与 SEO 站长 上线前检查标题/描述/结构化数据 Meta 长度与 SERP 预览、FAQ Schema 生成、hreflang 标签生成 自研 + fast-xml-parser meta description length, faq schema generator 否
电商目录与价格 目录字段清洗、折扣与含税价说明 折扣/含税价计算器（含税率假设表）、CSV 目录字段规范化 纯公式 + papaparse discount calculator tax included, csv product feed 弱 YMYL（价格说明须免责）
财务运营 运营指标解释，非投资建议 ROI（已有）、边际收益（已有）、复利/摊还（须公式+免责） 纯公式 compound interest formula, loan amortization 是
健康教育计算 筛查向教育计算，非诊疗 BMI（已有）、BMR/TDEE（须 WHO/CDC + 局限 FAQ） 纯公式 bmr calculator mifflin, bmi limitations 是

5.2 行业工具验收标准

立项前自问（任一「否」则暂缓）：

  1. 能否用一句话说明 哪个岗位在什么场景 使用？
  2. 页面能否写出 该行业才有的对照表/边界/标准引用（相对泛化竞品的 Information Gain）？
  3. 是否落在包调研的可行技术内，且 Tier 分层不破坏 CWV？

5.3 明确降级或拒绝的「泛化清单」

以下曾出现在旧竞品路线图中，不再作为默认 P0（除非改写成 AI/行业语境）：

旧候选 处理
独立 Unit Converter 超市页 降级；仅当嵌入行业场景（如电商体积重、烹饪计量专页）
独立 Password / QR / Word Counter 铺量 降级；可并入「站长/开发者」场景工具或暂缓
多个面积/百分比空壳变体 拒绝
AI 写作 / 付费墙工具超市 拒绝

6. 立项漏斗

每个候选工具打分（各 1–5，总分 ≥ 12 优先；9–11 须强化行业/AI 说明；≤ 8 暂缓）：

立项分 = 搜索意图明确度 × 行业或 AI 信息增益空间 × 包与工程可行性
维度 高分信号 低分信号
搜索意图明确度 单一动作词（validate / convert / count / estimate） 「online tool」类泛词
行业或 AI 信息增益 能写公式、字段映射、标准引用、失败案例 仅 UI 壳，与竞品同质
包与工程可行性 Tier 0/1；或 Tier 2 且可懒加载 需重后端、大模型托管、CWV 不可控

决策：优先「AI 桥接 + 一个行业深耕」并行，而不是跨主题每周堆 10 个薄页。

页面内容与 Google 合规要求见 工具页 SEO 与 Information Gain。

7. 优先级（重写）

7.1 本站现状（锚点）

已上线约 9 个工具（开发者 ×3、计算器 ×6）。缺口不再用「补齐竞品超市」来填，而用 §4 / §5 方向填。

7.2 P0（立即）— AI 桥接 + 开发者数据交换

工具 slug 方向 工程成本 差异化要点
JSON Schema Validator json-schema-validator AI + 开发者 低 错误路径解释 + 模型输出场景 FAQ
AI Token / Cost Estimator ai-token-counter AI 桥接 低 多模型价表 + 估算局限
Safe Paste Cleaner safe-paste-cleaner AI 安全 极低 零宽/隐藏字符对照表
Chat Export Converter chat-export-converter AI 桥接 中 字段映射 + 示例导出文件
YAML ↔ JSON yaml-json AI 数据 / 开发者 低 与 Schema 校验互链
Meta Description Length / SERP Preview meta-serp-preview SEO 站长行业 低 像素/字符规则 + 各引擎差异说明

P0 开工顺序建议：json-schema-validator → ai-token-counter → safe-paste-cleaner → yaml-json → meta-serp-preview → chat-export-converter。

7.3 P1 — 行业深耕 + 轻量 AI 扩展

工具 行业/方向 备注
Prompt Template Builder AI 桥接 与 Token 计数、Schema 校验互链
CSV ↔ JSON（目录/数据集） 电商 / 数据 示例用产品 feed 字段
FAQ / HowTo Schema Generator SEO 站长 Schema 与可见内容一致性说明
BMR / TDEE（教育） 健康 YMYL Mifflin-St Jeor + WHO/CDC；勿医疗建议
Compound Interest / Loan EMI 财务 YMYL 摊还表 + 非投资建议免责
OCR → Text（POC 后） AI 桥接 Tier 2；强调本地不上传

7.4 P2 / 暂缓

图片压缩、PDF 合并、完整 FFmpeg 转码、Transformers.js 摘要等：技术可行见包调研与音视频文档；仅在能绑定行业或 AI 流水线故事且 CWV 可控时再排期。

7.5 发布节奏

  • 每周 1–2 个高质量工具（含 10 语审核），优于每周 10 个薄页。
  • dateModified 仅在有实质更新时变更。
  • 成功指标：GSC 出现行业/AI 长尾查询；工具页 Information Gain checklist 全勾选。

8. 工程接入模板

src/site/tool-catalog.json          # 目录项（含 ymyl 等标记）

public/scripts/tools/{tool}.js      # 可选客户端脚本（Tier 分层）

内容区块与 Schema 最低标准见 工具页 SEO 与 Information Gain 与 SEO_TOOL_RULES。
