工具页 Google SEO 与 Information Gain

日期: 2026-07-28
标签: SEO, Google, Information Gain, E-E-A-T, 工具页
目标站点: https://onlinefreetools.org

关联文档:

  • 工具方向 — 做什么工具（AI 桥接 × 行业专属）
  • 工具页面 SEO 规则 — description / FAQ / YMYL lint 硬规则
  • SEO 分析与优化方案 — Sitemap、Schema 注入、CWV 基建
  • 外链策略 — 入站/出站合规
  • JS 工具包调研 — 技术可行性（非 SEO 优先级）

本文职责：回答「工具页如何符合 Google 规则，以及如何用 Information Gain 胜过同类工具页」。

1. 核心命题

合规（People-First / Spam / E-E-A-T）是底线；Information Gain 是相对竞品工具页的胜负手。

单页同时服务三方：

受众 页面须回答
用户 做什么？怎么用？结果可信吗？和我的行业/AI 场景有何关系？
Google 爬虫 主题是什么？与哪些查询匹配？与站内其他页关系？
AI Overviews 能否提取清晰步骤、公式、示例、边界作为引用片段？

不做：llms.txt、AI 专用 Schema、为 AI 阅读而刻意切块整站——Google AI features and your website 明确无额外技术要求。

2. Google 规则底线

2.1 政策要点（工具站）

来源 结论 对本站
Creating helpful content 奖励为人而写；批量操纵排名违反 spam 每工具须真实可交互 + 公式/步骤/示例
AI features and your website AI Overviews 无额外技术要求 标准 SEO + 深度内容即可
E-E-A-T Trust 对 YMYL 权重最高 健康/财务：免责 + 权威引用
Spam Policies 未审核机翻、无实质改日期、跨主题薄页铺量 控节奏；dateModified 仅实质更新

2.2 禁止清单

  • 创建 llms.txt 或「AI 专用」Schema.org 类型
  • 伪造作者、虚假评论、虚假 aggregateRating
  • 无实质功能差异的同类工具铺量
  • 机器翻译后未经人工审核直接上线
  • 健康/财务给出医疗或投资建议而无免责声明
  • 仅对爬虫可见、对用户隐藏的 FAQ（cloaking）
  • Schema 文本与可见内容不一致或夸大

2.3 YMYL（健康 / 财务）

元素 健康 财务
免责声明 非医疗建议，咨询医生 非财务/投资建议，咨询专业人士
公式来源 WHO、CDC 等 Investopedia、公开会计准则等
适用范围 运动员/孕妇等局限 利率假设、固定期限等
字段 tool_*_disclaimer + 建议 tool_*_references 同左

硬规则见 SEO_TOOL_RULES.md。

3. Information Gain 作战手册

Information Gain（信息增益）：相对 SERP 上同类工具页，用户读完本页后多带走的、可验证的信息。Google 质量框架与 helpful content 均强调「是否带来新价值」，而非更长的同质文案。

3.1 必赢差异维度（相对多数工具站）

每个新工具上线前，从下表勾选 至少 3 项，并在页面上可核对：

# 增益维度 本站做法 多数竞品缺失
1 公式 / 规则推导 写出计算式、字段映射、算法步骤，而非只出结果 仅输入框
2 边界与失败案例 非法输入、局限、常见坑 FAQ 无错误解释
3 行业或 AI 语境 Use cases 绑定岗位/流水线（见工具方向文档） 泛化「anyone can use」
4 对照表 模型价差、单位假设、引擎字符限制、标准版本差异 无表
5 权威引用 IETF / WHO / NIST / Schema.org 等可点外链 无 References
6 本地隐私 文件/粘贴内容浏览器处理；明确「不上传」 强制上传
7 多语言术语 10 语言本地化 title/H1/关键（人工审核） 仅英文
8 完整数值示例 ≥1 组 Input → Output（最好含边界例） 无具体数字
9 主题内链 Related tools ≥ 2；同行业/同 AI 链路互链 孤立页

3.2 每工具 IG 最低配额（硬性）

上线 PR 必须满足：

  1. ≥ 3 项 §3.1 增益，在 PR 描述或清单中逐条写明「页面哪一节体现」。
  2. 可见正文含 How it works + 至少 1 个完整 Example（计算/转换类另加 Formula/Rules）。
  3. FAQ ≥ 3（与 SEO_TOOL_RULES 一致；YMYL 须含局限性/免责类问题）；答案不得整段抄竞品。
  4. 至少 1 条 可点击权威引用（YMYL 建议 ≥ 2），或明确说明「规范即页面内嵌规则表」。
  5. 文件/粘贴类工具必须有 本地处理 FAQ 或声明。

3.3 反面模式（零增益）

反面 后果 正确做法
只有输入框 薄内容；难被引用 补 How / Example / FAQ
FAQ 复制竞品 无 IG 加入本地处理、行业边界、本站独有对照
空壳长尾变体页 spam 风险 合并为一带多场景的真工具
dateModified 无改内容却刷新 信任下降 仅实质更新时改
title 堆砌同义词 可能被视为 spam 一个主关键词 + 品牌
隐藏关键词文本 违规 全部可见
WASM 首屏拉 5MB CWV 差 点击后懒加载

3.4 AI Overviews 友好写法（仍是标准 SEO）

  • 步骤用有序列表，动词开头，与 UI 一致 → 易被抽成 HowTo 片段。
  • 公式单独成段，符号与示例数值一致。
  • FAQ 一问一答、直接回答，避免「见上文」。
  • 不需要 额外 AI SEO 文件或特殊 Schema。

3.5 立项时的 IG 预审（与工具方向漏斗衔接）

工具方向文档的「行业或 AI 信息增益空间」维度，在写文案前再落成检查表：

## IG 预审 — {Tool Name}
- [ ] 竞品 SERP 前 5 缺失什么？（列 3 条）
- [ ] 我们补哪 3 条增益？（对应 §3.1 编号）
- [ ] 权威来源 URL：
- [ ] 行业/AI Use case 文案草稿：
- [ ] 边界/失败案例草稿：

4. 单页结构模板

4.1 自上而下

Header
├─ 面包屑（Home → Topics? → Tool）
├─ H1 + 一句话摘要
├─ 【工具交互区】← 首屏，满足即时意图
├─ H2 How it works
├─ H2 Formula / Rules / Algorithm（计算与转换类）
├─ H2 Example
├─ H2 Use cases（行业或 AI 场景，2–3 条）
├─ H2 FAQ
├─ H2 Related tools
├─ H2 References
└─ Disclaimer（YMYL 必备）
Footer

原则：仅一个 H1；交互区尽量首屏可见；Canvas/纯图结果须另附可索引文字示例。

4.2 与 i18n / 代码字段

区块 字段 / 实现 状态目标
<title> tool_*_title + brand 主词靠前，约 50–60 英文字符
description tool_*_description 80–160 字符；步骤/公式 + 示例（lint:seo）
正文 tool_*_article 或分节字段 ≥ 约 300 词等效可见说明
How 步骤 tool_*_how_stepN 或 article 内 ol 3–5 步
FAQ tool_*_faq_qN / tool_*_faq_aN ≥ 3（lint 硬规则）
References tool_*_references YMYL 建议必有
Disclaimer tool_*_disclaimer ymyl: true 必有
JSON-LD layout / schema 注入 与可见文本一致
hreflang renderLayout alternates + x-default 与 sitemap URL 一致

4.3 Meta 要点

Title：{Primary Keyword + Action} | {Brand} — 不堆砌；各语言本地化。

Description 三段式：{一句话价值} + {Process/Formula} + {Example}

Canonical：apex https://onlinefreetools.org；默认语无前缀；其他 /{lang}/tools/{slug}。

细节与示例见历史单页文档已并入本节；硬校验以 npm run lint:seo 为准。

5. Schema 与结构化数据

实现细节见 SEO_ANALYSIS_PLAN.md。FAQPage / HowTo 富结果展示可能变化；问答仍须对用户可见，不要把富结果点击当 KPI（见 SEO_TOOL_RULES）。

工具类型 建议 Schema 禁止
交互工具 WebApplication +（可选）步骤结构化 虚假 aggregateRating
教程型 how-to-calculate-* Article + 步骤说明 夸大功效
支柱/集合页 CollectionPage / ItemList —
全站导航 BreadcrumbList —

规则：JSON-LD 每句须能在页面上找到对应可见文案。

6. 主题权威（最小必要）

主题集群服务于 内链与 Information Gain，不是为了铺工具数量。

要求 说明
支柱页（若做） 主题简介、工具列表、对比表（场景差异 = IG）、hreflang
子工具页 Related tools ≥ 2；优先链向同行业或同一 AI 流水线上下游
侧栏 同主题过滤优于全站无序列表

工具「做哪些」不在本文展开，见 工具方向。

7. 多语言 SEO

  • 10 语言是资产：title / h1 / description / FAQ 本地化；slug 保持英文 kebab-case。
  • 工作流：英文母版（公式+步骤+示例）→ 人工翻译审核 → lint:seo → build:site（sitemap 含全语言 URL）。
  • 禁止 GPT 批量翻译直出。

8. 技术 SEO 前置（阻塞）

新工具难收录时，优先修基建（详见 SEO_ANALYSIS_PLAN）：

优先级 任务
P0 Sitemap 收录全部工具 × 语言 URL
P0 工具页 JSON-LD 与可见内容一致
P0 Google Search Console
P1 面包屑；CWV 基线（尤其 Tier 2 WASM）

9. 发布、Checklist 与度量

9.1 发布节奏

  • 先保证收录管道，再每周 1–2 个高质量工具（含 10 语）。
  • 稳定期可放缓，把时间花在深化 IG（对照表、边界、引用），而非加薄页。

9.2 上线 Checklist（PR 合并前）

  • tool-catalog.json / 路由注册完成
  • 10 语言 title / description / article（或等价分节）齐全
  • npm run lint:seo 通过
  • IG ≥ 3 项（§3.1）已在 PR 写明
  • How + Example（+ Formula 如适用）可见
  • FAQ 数量达标；YMYL 有 disclaimer + references
  • Related tools ≥ 2（行业/AI 链路优先）
  • JSON-LD 与可见内容一致；无虚假评分
  • canonical / hreflang / x-default 正确
  • sitemap 构建后含本工具全语言 URL
  • 文件/粘贴类：本地处理声明
  • datePublished / dateModified 真实

11. 结论

合规底线 + 每页 ≥3 条可验证 Information Gain + 行业/AI 语境 + 多语言教育式说明 = 可排名、可被引用的工具页。

近期执行：新工具严格走 §9.2 Checklist；存量页按 §3.1 补齐公式/示例/边界/引用，而不是再堆泛化变体 URL。
