# 01 — 工具方向讨论

> 对照 `docs/2026-07-28-tool-direction.md`。一条工具只标一个**主方向**（A / B / C），不要硬凑三维交叉。

## 候选一句话

- 工具做什么：一次选多张商品照片，用同一套最长边 / 质量 / 目标 KB 有损压小，成功文件打 ZIP 下载。
- 谁在什么任务里用：电商运营、上架助理在上传前把一批 SKU 主图压到平台或邮箱体积上限。

## 主方向判定

| 选项 | 是否匹配 | 理由 |
|---|---|---|
| **A** 浏览器 JS 能力 | 是（主） | Canvas `toBlob` + 队列 + ZIP 都是成熟浏览器能力；相对单文件页增量在队列规则，不是新编码器 |
| **B** 场景桥接 | 部分 | 「多张商品图 → 可上传体积」是场景，但主卖点仍是浏览器批量作业，不单靠上下游桥 |
| **C** 行业专属 | 否 | 不是某一平台规范计算器；Amazon 规格是另一 slug 的芯片/后排页 |

**选定主方向**：A  
**次要互链参考**（可选，非立项条件）：`image-compress`（单张）、`image-format-converter`（改后缀不是本页）

## 红线自检

- [x] 不是仅改 title/slug 的空壳变体（队列、共享目标 KB 汇总、ZIP 重名、单张失败跳过相对单文件页是另一套主控件）
- [x] 不是无增量机翻铺量
- [x] 不依赖偏离定位的重后端
- [x] 长尾默认「一带多场景」，不轻易拆近义 URL（`compress jpg` / `jpeg` / `200kb` 只做芯片或 FAQ）

## 方向专属检查

### 若选 A

- 成熟度 / 推荐包：Canvas 2D + `HTMLCanvasElement.toBlob`（Tier 0）；ZIP 用现有站内 `fflate` UMD 模式
- Tier（0 / 1 / 2）：0（编码）+ 小体积 ZIP 库（与现有打包页一致）
- CWV / 懒加载注意：fflate 脚本与现有 ZIP 页一样同步引入；队列串行、一次只解码一张，避免同时撑满内存
