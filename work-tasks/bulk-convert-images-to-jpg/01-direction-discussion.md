# 01 — 工具方向讨论

> 对照 `docs/2026-07-28-tool-direction.md`。一条工具只标一个**主方向**（A / B / C），不要硬凑三维交叉。

## 候选一句话

- 工具做什么：一次选多张图，全部转成 `.jpg`（透明必须垫底），成功项打 ZIP。
- 谁在什么任务里用：填表、发邮件、打印、店铺上传只收 JPG 的人，手里是 PNG/HEIC/WebP。

## 主方向判定

| 选项 | 是否匹配 | 理由 |
|---|---|---|
| **A** 浏览器 JS 能力 | 是（主） | Canvas JPEG `toBlob` + 整批垫底规则 + 队列 + ZIP |
| **B** 场景桥接 | 部分 | 「必须交 JPG」是场景，主卖点仍是浏览器批量转换 |
| **C** 行业专属 | 否 | 不是单一平台规范计算器 |

**选定主方向**：A  
**次要互链参考**：`image-format-converter`（单张）、`image-compress`（压体积不是改后缀）

## 红线自检

- [x] 不是仅改 title/slug 的空壳变体（整批同一垫底、拒绝无垫底的透明图、`.jpg` 统一扩展名、失败跳过相对单文件转换页是另一套主控件）
- [x] 不是无增量机翻铺量
- [x] 不依赖偏离定位的重后端
- [x] 长尾默认「一带多场景」，不轻易拆近义 URL（png to jpg / heic to jpg / jpeg 写法并进本页）

## 方向专属检查

### 若选 A

- 成熟度 / 推荐包：Canvas 2D + `toBlob('image/jpeg')`；ZIP `fflate`
- Tier：0
- CWV：串行解码；HEIC 依赖浏览器能否解码，失败只记该行

### 若选 B

- 场景链：—
- 上游 / 下游工具：—

### 若选 C

立项三问：不适用。
