# 01 — 工具方向讨论

> 对照 `docs/2026-07-28-tool-direction.md`。一条工具只标一个**主方向**。

## 候选一句话

- 工具做什么：在浏览器里把多文件打成一个 ZIP 下载发出去（Gzip 单文件为次模式）。
- 谁在什么任务里用：发附件、交作业、打包源码，不想装 WinRAR / 不愿把文件上传到在线压缩站。

## 主方向判定

| 选项 | 是否匹配 | 理由 |
|---|---|---|
| **A** 浏览器 JS 能力 | 是 | A.5 ZIP；`fflate` zipSync；Tier 0/1 |
| **B** 场景桥接 | 次 | 发出去这一步；不作为主方向 |
| **C** 行业专属 | 否 | 无岗位专属规范 |

**选定主方向**：A  
**次要互链参考**：`unzip-file`、`archive-extractor`、`file-hash`

## 红线自检

- [x] 不是仅改 title/slug 的空壳变体（与解压方向相反）
- [x] 不是无增量机翻铺量
- [x] 不依赖偏离定位的重后端
- [x] 长尾默认一带多场景：folder / gzip / 可选密码提示，不拆 URL

## 方向专属检查

### 若选 A

- 成熟度 / 推荐包：`fflate`（与 unzip 同引擎）
- Tier：0/1
- CWV：UMD 脚本；样例小文件自动 ZIP

## 结论

- 继续立项：是
- 建议 slug：`create-zip-file`
- 与已上线工具关系：新建；Related `unzip-file`、`file-hash`
- 进入 `02` 前仍缺的信息：无
- 用户意图审查：见 `02`
