# 01 — 工具方向讨论

> 对照 `docs/2026-07-28-tool-direction.md`。一条工具只标一个**主方向**（A / B / C），不要硬凑三维交叉。

## 候选一句话

- 工具做什么：在浏览器内读取图片 EXIF/GPS/相机等元数据，并可一键清除后下载「干净」副本；文件不离开本机。
- 谁在什么任务里用：发帖/上架前去掉 GPS 与相机序列号；查清手机照片拍于何时何地；确认「清除后」是否还剩可读元数据。

## 主方向判定

| 选项 | 是否匹配 | 理由 |
|---|---|---|
| **A** 浏览器 JS 能力 | **是（主）** | A.2 明确「EXIF 读/清」+ `exifr`；隐私场景强；包调研亦列「EXIF 查看与一键清除」 |
| **B** 场景桥接 | 弱（叙事可借隐私场景，非主） | 不绑具名平台规格；不是 1→N 尺寸包 |
| **C** 行业专属 | 否 | 非单一垂直行话计算器 |

**选定主方向**：A  
**次要互链参考**（可选，非立项条件）：Related 挂 `image-format-converter`（清元数据后再转 WebP 上站）；未来可链 `image-compress`、平台图包。

## 红线自检

- [x] 不是仅改 title/slug 的空壳变体（真实读表 + 本地清除 + 边界说明）
- [x] 不是无增量机翻铺量（十语 locale brief + ≥3 轮）
- [x] 不依赖偏离定位的重后端（客户端 `exifr` + Canvas 重编码清除；库懒加载）
- [x] 长尾默认「一带多场景」，不轻易拆近义 URL（**拒绝**单独 `/tools/exif-viewer` 与 `/tools/remove-exif` / `strip-gps-from-photo` 空壳页）

## 方向专属检查

### 若选 A

- 成熟度 / 推荐包：✅✅✅；读：`exifr`；清：Canvas `drawImage` + `toBlob`（重编码剥离元数据，非字节级无损改写）
- Tier：**1**（`exifr` 首次交互/选文件后动态 import；清除路径 Tier 0 Canvas）
- CWV / 懒加载注意：勿首屏拉全量 `exifr`；大图软上限；清除 JPEG 时质量默认高并写明「非像素级无损」

### 若选 B

- （非主）场景备注：分享前脱敏 → 社交/电商上传；与格式转换可串成工作流

### 若选 C

- （不适用）
