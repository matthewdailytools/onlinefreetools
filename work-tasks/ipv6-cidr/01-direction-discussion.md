# 01 — 工具方向讨论

> 对照 `docs/2026-07-28-tool-direction.md`。一条工具只标一个**主方向**（A / B / C），不要硬凑三维交叉。

## 候选一句话

- 工具做什么：把一条 IPv6 CIDR（含压缩写法）展开成网络地址、末地址、地址数量，并做 RFC 5952 压缩/展开与 nibble 边界提示。
- 谁在什么任务里用：网络/云工程师规划 IPv6 前缀（LAN /64、点对点 /127、单主机 /128）或核对文档前缀 `2001:db8::/32`。

## 主方向判定

| 选项 | 是否匹配 | 理由 |
|---|---|---|
| **A** 浏览器 JS 能力 | **是（主）** | 纯 128-bit 位运算 + 文本规范化；Tier 0；无后端 |
| **B** 场景桥接 | 弱 | 可互链 IPv4 展开页，但本页不是旅程桥 |
| **C** 行业专属 | 弱 | 通用网络算子，非单一垂直行话页 |

**选定主方向**：A  
**次要互链参考**：`cidr-to-ip-range`（IPv4 对照）、`ip-range-to-cidr`（起止→前缀）

## 红线自检

- [x] 不是仅改 title/slug 的空壳变体（对象是 IPv6，算法与 IPv4 页不同：压缩/展开、nibble、/127）
- [x] 不是无增量机翻铺量
- [x] 不依赖偏离定位的重后端
- [x] 长尾默认「一带多场景」：`ipv6 cidr` / `ipv6 cidr calculator` / notation/chart 并入本页，不拆近义 URL

## 方向专属检查

### 若选 A

- 成熟度 / 推荐包：原生 JS BigInt；**无** npm IP 包（与现有 CIDR 页一致）
- Tier（0 / 1 / 2）：0
- CWV / 懒加载注意：无 WASM；计算即时

- 继续立项：是
