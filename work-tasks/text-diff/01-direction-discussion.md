# 01 — 工具方向讨论

> 对照 `docs/2026-07-28-tool-direction.md`。一条工具只标一个**主方向**（A / B / C），不要硬凑三维交叉。

## 候选一句话

- 工具做什么：在浏览器内对两段文本做行/词/字符级 Diff，高亮增删改，并说明对比规则与边界。
- 谁在什么任务里用：开发者核对配置/代码片段；写作者/译者对照改稿；Prompt 工程师对比提示词迭代。

## 主方向判定

| 选项 | 是否匹配 | 理由 |
|---|---|---|
| **A** 浏览器 JS 能力 | **是（主）** | 文档 A.1 明确候选：「文本 Diff / `diff` / 行·词级」；成熟度 ✅✅✅；Tier 1 小包 |
| **B** 场景桥接 | 弱 | 可写「原稿→改稿」场景叙事，但核心是技术能力工具，不必挂主方向 B |
| **C** 行业专属 | 否 | 非单一垂直行话；避免做成「又一个通用对比超市」换皮 |

**选定主方向**：A  
**次要互链参考**（可选，非立项条件）：开发者工具链（`markdown-to-html`、`website-headers`）；未来 `yaml-json` / `safe-paste-cleaner`（粘贴清洗后再 Diff）

## 红线自检

- [x] 不是仅改 title/slug 的空壳变体（真实交互 + 规则/边界/示例）
- [x] 不是无增量机翻铺量
- [x] 不依赖偏离定位的重后端（纯客户端）
- [x] 长尾默认「一带多场景」，不轻易拆近义 URL（`diff checker` / `compare text` / `文本对比` 等同页覆盖）
