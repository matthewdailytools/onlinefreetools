# 01 — 工具方向讨论

> 对照 `docs/2026-07-28-tool-direction.md`。一条工具只标一个**主方向**（A / B / C），不要硬凑三维交叉。

## 候选一句话

- 工具做什么：在浏览器内打开 ZIP 压缩包，列出文件树，预览常见文本/图片，下载单个文件或把全部内容安全导出。
- 谁在什么任务里用：办公、学生、开发者、移动端用户在无法安装桌面解压软件或不想上传私密文件时，快速查看和取出 ZIP 中的文件。

## 主方向判定

| 选项 | 是否匹配 | 理由 |
|---|---|---|
| **A** 浏览器 JS 能力 | 是 | 方向文档 A.5 已标 ZIP 解压为成熟能力；`fflate` / `jszip` Tier 1 可在浏览器解析 ZIP 目录与内容。 |
| **B** 场景桥接 | 次要 | 输入 ZIP → 输出文件/文件夹或重新打包下载，是文件工作流中的桥接步骤，但核心立项依据是浏览器文件处理能力。 |
| **C** 行业专属 | 否 | 不依赖垂直行业术语或行业规范。 |

**选定主方向**：A  
**次要互链参考**：文件处理集群；与 `create-zip-file`、`file-hash`、`split-pdf` 互链。

## 红线自检

- [x] 不是仅改 title/slug 的空壳变体：首版有真实 ZIP 解析、文件树、预览、下载与安全边界。
- [x] 不是无增量机翻铺量：后续实现前按十语 brief 重写，不用同构翻译直出。
- [x] 不依赖偏离定位的重后端：ZIP 解压在浏览器内完成，不需要上传或后端队列。
- [x] 长尾默认「一带多场景」，不轻易拆近义 URL：`extract zip`、`unzip online`、`zip viewer` 放在同页 Use cases / FAQ；RAR / 7Z 后续再评估 `extract-archive`。

## 方向专属检查

### 若选 A

- 成熟度 / 推荐包：ZIP 核心路径非常成熟；优先 `fflate`，必要时用 `jszip` 补 ZIP64 / 兼容性行为。
- Tier（0 / 1 / 2）：Tier 1；ZIP 引擎随工具交互区加载或首次选择文件时加载。多格式归档若后续做，另用 Tier 2 懒加载。
- CWV / 懒加载注意：首屏只加载基础 UI 和小样例；大 ZIP 解析放 Web Worker；RAR / 7Z 引擎不得随首屏加载。
